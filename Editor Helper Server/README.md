# Editor Helper Server

Сервер каталога Editor Helper и веб-админка. WPF-клиент находится в соседней папке репозитория `../Editor Helper Client`.

## Требования

- Windows 10 или 11
- .NET SDK 8.0 или новее

## Запуск

Из этой папки запусти:

```powershell
dotnet run --project EditorHelper.Server
```

Или открой `run-server.cmd`. Сервер доступен по адресу `http://127.0.0.1:5080`, админ-панель — `http://127.0.0.1:5080/admin`. Для локальной разработки с одноразовым входом запусти `run-local.ps1` в PowerShell. Development-вход работает только при `ASPNETCORE_ENVIRONMENT=Development` и `EDITORHELPER_ENABLE_DEV_LOGIN=true`; не открывай этот режим в локальную сеть или интернет.

При первом запуске сервер создаёт `EditorHelper.Server/server-data/admin-token.txt`. Введи токен на странице входа в Admin. Секреты сервера хранятся в `server-data/secrets.json` или задаются переменными окружения; их нельзя помещать в клиентскую папку.

## Структура

- `EditorHelper.Server/` — ASP.NET Core API, админ-панель, общий Bot API-клиент и каталоговое хранилище.
- `../Editor Helper Telegram Bot/TelegramBotService.cs` — обработчики входа, административного меню и документов канала для единственного Telegram-бота; сервер подключает этот файл как linked source и запускает один polling-процесс.
- `tests/EditorHelper.Server.Tests/` — серверные интеграционные тесты.
- `Data/` — отдельный seed-каталог, который копируется в сборку сервера и используется только для первоначального заполнения.
- `EditorHelper.Server/server-data/` — изменяемый каталог сервера, обнаруженные Telegram-файлы, загруженные архивы и секреты.

Seed-каталог копируется только когда серверный каталог пуст. После импорта сервер не зависит от клиентской папки. Чтобы подключить приложение-клиент к локальному серверу, в настройках клиента укажи `http://127.0.0.1:5080`.

## Сборка и проверки

```powershell
dotnet build EditorHelper.Server.sln
dotnet run --project tests/EditorHelper.Server.Tests
```

Интеграционные тесты используют `DownloadService` клиента и ожидают клиентский проект по соседнему пути `..\Editor Helper Client\EditorHelper.csproj`.

## Telegram-вход и Admin-бот

Используй одного уже созданного Telegram-бота от `@BotFather`; отдельный auth- или admin-бот не нужен. Для локальной настройки задай его единственный токен и username в PowerShell до запуска:

```powershell
$env:TELEGRAM_BOT_TOKEN = '<единый токен Telegram-бота>'
$env:TELEGRAM_BOT_USERNAME = '<username_бота_без_@>'
$env:EDITORHELPER_OWNER_TELEGRAM_ID = '<числовой Telegram ID владельца>'
$env:TELEGRAM_BOT_TOKEN = '<token бота канала, если используется каталог>'
$env:TELEGRAM_CHANNEL_ID = '<ID канала>'
.\run-local.ps1
```

Единый Telegram-бот одновременно подтверждает одноразовые коды входа, обрабатывает команды управления и обнаруживает документы канала; все функции используют один polling-цикл и один токен. Клиентский Telegram ID не принимается как доказательство личности. Роль Owner задаётся серверной переменной `EDITORHELPER_OWNER_TELEGRAM_ID` (постоянный числовой Telegram ID, не username). Токен не включай в исходники и не помещай в репозиторий.

Клиент подключается к `http://127.0.0.1:5080`; на форме входа выбери «Войти через Telegram», открой единого бота, отправь `/start`, затем показанный код и нажми «Проверить авторизацию». Кнопка «Отменить вход» инвалидирует challenge. Выйти можно кнопкой с именем/ролью в верхней части окна.

Управление пользователями в этом же боте и доступно только Owner: отправь `/start`; выдача и снятие VIP (`/role <Telegram ID> <user|vip>` или inline-кнопки в карточке пользователя), блокировка и отзыв сессий требуют отдельного подтверждения inline-кнопкой и повторной серверной проверки роли. Поиск выполняется командой `/find <внутренний ID или Telegram ID>`, профиль — `/userinfo <Telegram ID>`. Документы каталожного канала продолжает обнаруживать тот же бот.

## Роли

В системе ровно три роли:

| Роль | Возможности |
|---|---|
| `User` | Обычный доступ: каталог, загрузка, избранное. Назначается по умолчанию. |
| `VIP` | Обычный доступ плюс статус VIP и бейдж в интерфейсе. |
| `Owner` | Полный доступ: управление приложением, выдача и снятие VIP, блокировки, аудит. Только один аккаунт, определяемый по `EDITORHELPER_OWNER_TELEGRAM_ID`. |

Выдавать роли может только Owner; роль Owner через API не присваивается и не снимается — она привязана к конфигурации сервера. Самостоятельно повысить себе роль нельзя ни через клиент, ни прямым запросом: каждая операция смены роли проверяет текущего актора на сервере. Старые базы мигрируются автоматически при запуске: `Beta Tester` → `VIP`, прежний владелец → `Owner`, упразднённый `Admin` → `User`; аккаунты, избранное и сессии сохраняются.

## Привязка аккаунта к устройству

Один аккаунт работает только с одного устройства одновременно. Клиент при входе отправляет `deviceId` — криптослучайный ключ из 256 бит, который генерируется один раз и хранится на устройстве в `Data/device.key` под Windows DPAPI (CurrentUser). IP, MAC и User-Agent не используются: они неуникальны и подделываются. На сервере хранится только SHA-256 хеш идентификатора, поэтому даже при утечке базы сопоставить запись с устройством нельзя. Приватный ключ никогда не покидает устройство.

- **Первый вход** с устройства привязывает аккаунт к нему автоматически.
- **Повторный вход** с того же устройства проходит как обычно.
- **Вход с другого устройства** отклоняется (HTTP 409) с сообщением отвязать текущее устройство.
- **Отвязка** выполняется в Telegram-боте: `/devices` или «📱 Мои устройства» показывает привязанное устройство, «Отвязать устройство» через подтверждение inline-кнопкой снимает привязку и закрывает все сессии аккаунта. После этого можно войти с другого устройства.

Все проверки выполняются на сервере. Владелец аккаунта определяется по Telegram ID из проверенного сервером апдейта, а не по данным клиента, поэтому отвязать чужой аккаунт подменой Telegram ID нельзя. Отвязка ограничена частотой (не более трёх в час на Telegram ID) и пишется в журнал аудита (`device.bound`, `device.conflict`, `device.unbound`, `device.unbound.by_owner`). Owner может отвязать устройство другого пользователя через его карточку в боте. Клиент без `deviceId` (например, dev-вход) работает без привязки — как раньше.

Для изолированного локального теста без Telegram сохрани текущий Development-вход; он отключён при Production. Чтобы очистить локальное состояние, сначала останови сервер и удали только `EditorHelper.Server/server-data/identity.db*` (сбросит пользователей/сессии/аудит) или удали весь `server-data` только если согласен также удалить локальный каталог/файлы/секреты.

Для разработки без Telegram можно настроить `EDITORHELPER_ENABLE_DEV_LOGIN=true`; не выставляй listener за пределы loopback. Production требует HTTPS и отдельных секретов; после переноса на VPS отключи Development и legacy-token switches.

## Безопасность

Админ API закрыто индивидуальными Bearer-сессиями после входа; старый `X-Admin-Token` разрешён только при явном Development-флаге как локальный bootstrap. Внешние ссылки проверяются на SSRF, а файлы отдаются потоком. Сессии, пользователи, роли и аудит хранятся в SQLite-файле `identity.db` внутри каталога данных. Токены и секреты не записывай в клиентское приложение или исходники.
